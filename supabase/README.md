# Supabase / Postgres migrations

> **Use this folder instead of the legacy `scriptDBCompleta.sql`.**
> See [`../docs/migration-history.md`](../docs/migration-history.md) for the full transition plan.

## How to apply

### Option A — Supabase SQL editor (recommended for first-time setup)

1. Open your Supabase project → **SQL Editor**.
2. Run the files **in order** (each one is idempotent where possible):
   1. `migrations/001_extensions_and_types.sql`
   2. `migrations/002_core_auth.sql`
   3. `migrations/003_access_and_audit.sql`
   4. `migrations/004_programs.sql`
   5. `migrations/005_virtual_records.sql`
   6. `migrations/006_nursing_and_appointments.sql`
   7. `migrations/007_functions.sql`
   8. `migrations/008_permissions.sql`
   9. `migrations/009_virtual_file_procedures.sql`
3. Optionally run `seeds/000_seed_roles.sql` to insert the default roles.

### Option B — Supabase CLI

```bash
# from the repo root
supabase db push
# or apply each file individually
psql "$DATABASE_URL" -f supabase/migrations/001_extensions_and_types.sql
psql "$DATABASE_URL" -f supabase/migrations/002_core_auth.sql
# ... etc.
```

## What changed vs. `scriptDBCompleta.sql`

| MySQL | Postgres / Supabase |
|---|---|
| `AUTO_INCREMENT` | `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `ENUM('a','b')` | `CREATE TYPE ... AS ENUM ('a','b')` then use the type |
| `DATETIME` | `TIMESTAMPTZ` (timezone-aware) |
| `` `backticks` `` | unquoted lowercase identifiers |
| `DELIMITER $$ ... PROCEDURE` | `CREATE OR REPLACE FUNCTION ... LANGUAGE plpgsql` |
| `ON UPDATE CURRENT_TIMESTAMP` | `BEFORE UPDATE` trigger (`set_updated_at()`) |
| `BOOLEAN DEFAULT FALSE` | Compatible (no change) |
| `TINYINT UNSIGNED` | `SMALLINT` |
| `SMALLINT UNSIGNED` | `SMALLINT` |
| `INT AUTO_INCREMENT` | `INTEGER GENERATED BY DEFAULT AS IDENTITY` |
